# Freight Load Rate Prediction

Predicts `posted_rate` for freight loads from load-level features (distance, weight,
equipment, origin/destination city, and market-condition signals), and produces:

- `outputs/validation_predictions.csv` — predicted rates for the 12,000 loads in `data/validation.csv`
- `outputs/december_predictions.csv` — predicted rates for the fixed December 2025 lane, validated and charted via the provided `score.py`
- `report/report.docx` — write-up of the approach, validation strategy, and results

## Repo structure

```
freight-rate-prediction/
├── data/
│   ├── train-test.csv                        # labeled development data (Jan–Oct 2025)
│   ├── validation.csv                        # 12,000 loads to predict (Nov 2025)
│   ├── december-chart-inputs.csv              # 31-day fixed-lane file for the required chart
│   ├── validation-predictions-template.csv    # load_id template to fill
│   └── processed/                             # generated by 02_feature_engineering.ipynb
├── notebooks/
│   ├── 01_eda.ipynb                # exploration, data-quality findings
│   ├── 02_feature_engineering.ipynb # cleaning, features, encoders, time-based split
│   └── 03_modeling.ipynb           # model comparison, selection, final predictions
├── models/
│   └── final_models.pkl            # fitted production models (full + no-market fallback)
├── outputs/
│   ├── validation_predictions.csv
│   ├── december_predictions.csv
│   └── scorer_results/
│       └── candidate_december.png   # produced by score.py
├── report/
│   └── report.docx
├── score.py                         # provided validator/scorer — do not modify
├── requirements.txt
└── README.md
```

## Setup

Requires Python 3.10+.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m ipykernel install --user --name=freight-rate-prediction
```

Open the notebooks in Jupyter/VS Code and select the `freight-rate-prediction` kernel.

## How to run

Run the three notebooks **in order** from the `notebooks/` folder — each one reads
inputs produced by the previous one via relative (`../data/...`) paths, so they must
be run from inside `notebooks/`:

1. **`01_eda.ipynb`** — exploratory analysis. No inputs required beyond `data/`; produces no files, just findings that inform the next two notebooks.
2. **`02_feature_engineering.ipynb`** — cleans known data-quality issues, engineers features, fits encoders, and writes everything to `data/processed/` (six feature CSVs + `feature_config.pkl`).
3. **`03_modeling.ipynb`** — loads `data/processed/`, compares candidate models on a time-based holdout split, selects a final model, retrains on all labeled data, and writes:
   - `outputs/validation_predictions.csv`
   - `outputs/december_predictions.csv`
   - `models/final_models.pkl`

   It then calls `score.py` directly (as a subprocess) to validate both output files and regenerate `outputs/scorer_results/candidate_december.png` — no separate manual step needed.

To re-run `score.py` by hand instead:

```bash
python score.py \
  --predictions outputs/validation_predictions.csv \
  --december-predictions outputs/december_predictions.csv \
  --output-dir outputs/scorer_results
```

## Approach summary

- **Validation strategy**: `validation.csv` (Nov 2025) and `december-chart-inputs.csv` (Dec 2025) both fall after the training window (Jan–Oct 2025), so a random split would overstate accuracy. Model selection instead uses a **time-based holdout** — the last 6 weeks of training data — to genuinely test forward-in-time forecasting. Full reasoning and results are in `notebooks/02_feature_engineering.ipynb` (split) and `notebooks/03_modeling.ipynb` (model comparison), and summarized in `report/report.docx`.
- **Data quality issues found and fixed**: sign-flipped negative `weight` values, rate-per-mile outlier rows, missing `weight`/`market_index` (imputed with indicator flags), 8 cities in validation never seen in training (handled with a target-encoding fallback to the global mean), and `december-chart-inputs.csv` lacking `market_index`/`quote_signal` entirely (handled with a dedicated fallback model). Details in `notebooks/01_eda.ipynb` Section 14 and `notebooks/02_feature_engineering.ipynb`.
- **Final model**: Linear Regression on `log1p(posted_rate)` with engineered distance, cyclical temporal, market-signal interaction, equipment, and target-encoded city features (holdout MAE $120.34, MAPE 5.57%, R² 0.830). A second model with the same architecture but without market-signal features generates the December predictions (holdout MAPE 7.29%).

See `report/report.docx` for the full write-up, and `notebooks/03_modeling.ipynb` for the code walkthrough.
